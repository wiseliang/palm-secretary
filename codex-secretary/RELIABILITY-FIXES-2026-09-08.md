# 审核问题修复记录

## 已实现

- 状态文件仅在确实不存在时初始化。格式损坏、未知版本、无效记录或迁移失败会保留原件并停止启动。
- 每次保存前保留上一份已提交状态为 `.palm/state.json.backup`。写入失败后回退内存，拒绝已排队的旧快照，后续操作可重新保存。
- 请求在调用 `turn/start` 前持久化，以 `clientRequestId` 保留去重记录；提前到达的执行和完成事件绑定到预登记任务。结果不确定时不自动重发。
- 未确认的请求显示“待核对”，重启后仍阻止同项目新任务；用户查看对话及成果、确认无运行任务后可解除阻塞，原请求编号仍保留。解除阻塞不会停止服务器任务。
- 子进程处理 spawn/error、stdin/error、初始化失败与退出，清理待处理请求和失败的初始化 Promise，下一次请求按退避间隔重试。
- 文件访问拒绝符号链接及目录链接；Linux 下载/预览验证已打开的文件描述符，删除使用目录描述符锚定目标。此措施不是全权限 Codex 进程的安全沙箱。
- WebSocket 在消息处理及执行前复验会话，并定期清理过期连接。退出登录撤销对应 Cookie、关闭关联连接；撤销记录以哈希落盘，成功登出后重启不会恢复旧 Cookie。
- CI 使用统一 `test:all` 入口，自动包含版本号回归脚本，新模型、CLI 检查及本轮故障回归均纳入。
- 更新根 README 的版本说明，区分 Web/API、Android 与鸿蒙的独立版本及验收状态。

## 状态恢复

出现状态文件错误时先停止 API 服务，保留整个 `.palm` 目录和项目目录副本。检查 `state.json.backup` 的内容及时间；该文件只保留上一份提交，不能替代独立的定期备份。确认采用它后，在服务停止期间将它复制为 `state.json`，再启动 API 并核对项目和任务列表。不要删除损坏原件，也不要通过清空 state.json 强行启动。

新文件 `.palm/revoked-sessions.json` 也应随状态备份保留；缺失旧撤销记录会失去对旧 Cookie 的撤销信息。若必须恢复更早的状态，应同时轮换 SESSION_SECRET 使所有旧会话失效。
