# v0.15.8 发布与回滚清单

发布范围：本次可靠性修复，仅掌心助理 Web/API。保持既有域名、反向代理、数据库、系统账号、执行权限和原生安装包不变。

## 切换前

1. 校验发布包 SHA256，确认包内版本为 0.15.8。包内只有源码、锁文件和非秘密构建配置；不含生产环境变量、账号或会话。
2. 记录 `/opt/palm-secretary/current` 的真实目标及两个服务的状态，确认实际部署路径、工作目录与既有 systemd 配置一致。不要根据旧 README 猜测线上配置。
3. 检查工作区 `.palm/state.json` 可解析，统计运行中与 submissionPending 任务数量。若存在未完成任务，停止发布，先等待或由用户处理；不要为升级自动终止任务。
4. 确认磁盘剩余不少于 5 GiB。在独立 release 目录构建，使用 codex 普通用户执行安装、检查、17 组回归及构建，避免把缓存或文件写成 root 所有。禁止在 current 中安装依赖或覆盖源码。
5. 切换前再次检查无任务运行。停止 API 后备份 `.palm` 整体目录，保留原属主和权限；备份不可置于公开下载目录。不要复制或打印环境变量和 Codex 凭据。

## 发布

1. 原子切换 current 到新 release，重启 `palm-secretary-api.service` 和 `palm-secretary-web.service`。
2. 确认两个服务均 active，未连续重启；检查本机 API health、Web 首页和现有 HTTPS 入口响应。
3. 检查日志有无启动异常、存储失败和权限错误，不输出凭据、Cookie 或业务内容。
4. `/api/health` 只是存活检查；不能据此宣布真实 Codex 任务端到端验收完成。独立回归使用 mock，不操作用户真实项目。真实登录、上传下载和短任务需在用户会话中完成验证。

## 失败回滚

1. 停止新的 API/Web，把 current 原子切回已记录的旧 release，恢复与升级直接相关的状态备份，再重启两个服务。
2. 若新版本已接受用户任务或产生新数据，不得直接用旧备份覆盖状态，先保全当前 `.palm` 并停止自动回滚，报告待核对的差异。
3. 回滚代码必须注意：旧版不读取会话撤销记录，已经退出登录的旧 Cookie 可能重新生效。需要回滚时一并轮换 SESSION_SECRET 使所有旧会话失效，并告知用户重新登录；不得打印新旧密钥。
4. 验证旧服务与入口恢复。保留失败 release 和日志便于诊断，不删除用户项目、上传文件、成果、Codex 配置或其他服务数据。

上线结果必须分开报告：候选源码校验、Linux 构建与回归、服务切换、入口健康、真实用户功能验收。未执行的检查不能填写为通过。
