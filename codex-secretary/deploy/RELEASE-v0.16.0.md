# v0.16.0：自动核对执行结果

## 行为变化

- 服务重启或 Codex 连接中断后，尚未确认结束的请求保留为待核对，并保留执行前的成果快照。
- 每 15 秒检查运行中或待核对任务；读取任务列表时也会触发受间隔限制的后台核对。
- 已取得执行编号时按编号匹配；编号丢失时，仅在提交前历史与本次输入摘要能够唯一确定新执行记录时恢复状态。
- 新对话历史暂不可用时仍允许正常提交，但不推断缺少编号的请求。历史缺失、状态未知、匹配不唯一时继续保留阻塞，不自动重跑。
- 待核对任务增加“重新核对执行历史”按钮，保留人工核对入口。人工处理后的结果不会被晚到的核对覆盖。
- 完成事件优先采用执行记录中的实际状态，避免把失败执行误记为完成。

## 验证

新增 tests/task-reconciliation-v025.mjs，覆盖唯一匹配、歧义、错误对话、缺失历史、未知状态、重启持久化、成果归属、并发合并、冷却间隔、人工处理竞态、失败结果，以及启动回执与完成事件同时丢失时的 HTTP/WebSocket 恢复和请求去重。

本地验证通过：npm run check（0 错误，1 条既有 img 性能提示）、npm run test:all（全部 18 组）、npm run build（Web 与服务端生产构建）。测试使用本地模拟 Codex，不代表生产真实任务验收。
